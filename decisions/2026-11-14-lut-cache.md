## Decision: Loaded LUTs are cached in `CubeLUT.cached(url:)`, keyed by path + modification date + size (8 entries, least recently used out); `CubeLUT.libraryFolder` is set up once per launch
## Context: `useLUT` re-read the .cube file on the main thread on every LUT selection and every Visual Design group switch (333 ms for a 65-point LUT before the parser was sped up). The old `visualLUTCache` was keyed by file name only, was never emptied, and went stale if a LUT was replaced under the same name.
## Alternatives considered: Keep the name-keyed dictionary and add invalidation; parse on a background queue.
## Reasoning: One cache in the type that owns the data serves both call sites (`useLUT`, `cachedLUT`), a file check per lookup keeps it correct when the file changes, and with a hit costing ~0.07 ms there is nothing left to move off the main thread. `importToLibrary` seeds the cache with the copy it just validated.
## Trade-offs accepted: One `stat` per lookup. `libraryFolder` no longer re-creates the folder if it is deleted while the app is running (`importToLibrary` still does).
## Supersedes: none
